# 开奖数据与中奖测算规则

核查日期：2026-08-26

## 1. 数据源结论

大乐透和双色球官网均存在前端正在使用的 JSON 接口，能够按期号返回开奖号码和奖级奖金，足以支持本地中奖测算，不需要解析网页或识别开奖截图。

这两个接口没有公开开发者文档、API Key 申请、SLA、版本兼容承诺或明确商用再发布授权，应称为“官网内部接口”，不能称为“官方开放 API”。V1 无服务器阶段允许通过 Repository 隔离后，由用户操作触发低频直连验证；不得后台抓取或批量归档。公开发布前需要取得书面许可。

## 2. 大乐透开奖接口

官方历史开奖页：

- https://www.lottery.gov.cn/kj/kjlb.html?dlt

官网前端调用代码：

- https://static.sporttery.cn/res_1_0/jcw/default/kj/kjCommonFun.js
- https://static.sporttery.cn/res_1_0/jcw/default/kj/dltKj.js

单期查询：

```http
GET https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry
    ?gameNo=85
    &provinceId=0
    &pageSize=1
    &pageNo=1
    &isVerify=1
    &startTerm=26091
    &endTerm=26091
```

最新开奖聚合接口仅用于辅助核对当前最新一期，不作为历史期号主查询：

```http
GET https://webapi.sporttery.cn/gateway/lottery/getDigitalDrawInfoV1.qry
    ?param=85,0
    &isVerify=1
```

读取 `value.dlt` 的 `lotteryGameNum`、`lotteryDrawNum`、`lotteryDrawResult`、`verify` 和 `lotteryNotice`。辅助接口期号不是目标期号、字段缺失或与主接口冲突时，不得用它覆盖主接口；目标是非最新历史期号时，改用主接口返回的 `drawPdfUrl` 或官网历史开奖页辅助复核。

关键参数：

| 参数 | 含义 |
|---|---|
| `gameNo=85` | 大乐透 |
| `provinceId=0` | 全国玩法 |
| `isVerify=1` | 查询已审核数据 |
| `startTerm/endTerm` | 闭区间期号，同值为单期 |
| `pageNo/pageSize` | 分页，页码从 1 开始 |

响应必须同时检查 HTTP 状态和业务层：

```text
success == true
errorCode == "0"
value.list 中存在目标期号
verify == 1
lotteryDrawResult 可解析为 5+2 个合法号码
```

主接口必须同时满足 `lotteryDrawStatus=20`、`lotteryNotice=1` 和 `lotteryPromotionFlag=0`；`drawPdfUrl` 用于最新聚合接口已经滚动到其他期号时的历史公告回退，不能单独证明开奖结果。

关键字段：

```text
lotteryDrawNum
lotteryDrawTime
lotteryDrawResult
lotteryDrawStatus
verify
prizeLevelList
drawPdfUrl
lotteryPaidBeginTime
lotteryPaidEndTime
```

解析风险：

- 金额和注数可能带千位逗号。
- 无中奖注时金额可能是 `---`，格式化金额可能为 `-1` 或 `0`。
- 历史数据中字段可能在字符串、数字、空串和对象之间漂移。
- 奖级数量随规则和派奖变化，不能按固定数组下标解析。
- HTTP 200 仍可能是业务失败。
- 空列表只表示目标期次暂无已发布数据，绝不表示未中奖。

2026-08-13 实测历史范围为 `07001` 至 `26091`，约 2909 期。

### 3.1 V1.3 走势图会话采样

走势图与单期中奖核对使用独立仓库契约，只读取期号、开奖日期和开奖号码，不把单一历史列表响应当作中奖金额的双源证据。用户进入某一彩种走势图时，以列表接口实际返回的第一条已发布记录为最新期锚点，向前取得最多 500 期：

- 大乐透省略 `startTerm/endTerm`，固定 `pageSize=100` 并按 `pageNo=1..5` 分页；官网实测会把超过 100 的页大小限制为 100。
- 双色球省略 `issueStart/issueEnd`，使用 `pageNo=1&pageSize=500` 单页读取。
- 页面只提供 `50 / 80 / 120 / 300 / 500` 期，最后一期必须等于当前官网最新已发布期。
- 每条记录严格校验玩法、发布状态、期号、日期年份、号码数量、范围、唯一性和升序；每页及合并结果校验重复期号、记录数量和最新期在前顺序。
- 规范化结果按开奖时间正序放入当前控制器会话内存；切换区域和期数不重复请求。应用重启后重新加载，不保存原始响应或规范化历史样本。
- 网络或结构异常直接显示不可用并等待用户主动重试，不使用演示数据、猜测期号或部分页面兜底。

该会话采样不后台执行、不长期归档，也不改变当前接口缺少公开授权的结论。公开分发、商业化、长期存储和再展示仍需书面许可或替换为明确授权的数据源。

关键字段：

```text
state
message
result[].code
result[].date
result[].red
result[].blue
result[].prizegrades[].type
result[].prizegrades[].typenum
result[].prizegrades[].typemoney
result[].fyjCount
result[].fyjMoney
result[].specialRuleInfo
result[].prizeSpecialInfo
result[].poolmoney
result[].detailsLink
```

响应处理：

```text
state == 0 且 result 中恰好存在目标期号：继续校验
message 包含“没有查到数据”：映射为开奖数据尚不可用
其他 state/message：映射为上游错误
```

解析风险：

- 奖金和注数先使用 `String` 接收；历史派奖金额可能包含中文说明。
- `findDrawNotice` 和 `forIssue` 的 `name`、`date` 格式不完全相同，必须在适配层归一化。
- `forIssue` 不返回 `fyjCount`、`fyjMoney`、`specialRuleInfo` 和 `prizeSpecialInfo`。特别规定期间若只用该接口，会把命中 `3` 个红球且未中蓝球的福运奖漏判为未中奖。
- `prizeSpecialInfo` 非空不一定代表额外奖项。当前只接受同时包含“一等奖”“奖金总额超出1亿元”“一等奖封顶规定”“调整后金额详见”的已核实封顶说明，单注奖金仍以奖级表为准；其他非空说明在完成规则建模前一律停留在 `PUBLISHING`。
- `prizegrades.type=7` 在已确认存在福运奖的 `2026014` 期仍可能为空，不能用它替代 `fyjCount/fyjMoney`。
- `issueCount`、期号区间和日期区间视为互斥筛选条件。
- 接口没有跨域响应头，但原生 Android、iOS 和 JVM Desktop 不受浏览器 CORS 限制。
- 响应声明 `no-cache, no-store`，且 `robots.txt` 限制查询 URL；未获许可前应低频使用并避免将可访问性误解为授权。
- 2026-08-13 实测仅覆盖 `2013001` 至今；2013 年以前需要其他正式档案源。

## 4. 统一开奖模型与校验

两个源必须映射到统一 `DrawResult`，原始 DTO 不得进入 UI 和规则引擎。

统一校验：

- 体彩期号为 5 位数字；福彩期号为 7 位数字。
- 大乐透前区 5 个唯一号码，范围 1 至 35；后区 2 个唯一号码，范围 1 至 12。
- 双色球红球 6 个唯一号码，范围 1 至 33；蓝球 1 个，范围 1 至 16。
- 目标期号和响应期号一致。
- 开奖日期合理。
- 奖级金额和注数不可为负数；不可解析金额保留原文并使用 `null`，不得转成 0。
- 同一彩种和期号的内容哈希变化时生成新修订并提示复核。

状态映射：

```text
无记录 → NOT_PUBLISHED
记录存在但尚未满足稳定性、规则政策或完整性条件 → PUBLISHING
号码稳定且当期规则和特别政策状态可确定 → FINAL_NUMBERS
奖级金额和附加奖金也完整 → FINAL_PAYOUT
设备离线、DNS 或连接超时 → NETWORK_UNAVAILABLE
HTTP/业务失败、响应解析失败或字段结构变化 → SOURCE_UNAVAILABLE
当前结果与主动刷新结果冲突 → CONFLICT
```

`FINAL_NUMBERS` 允许判断是否中奖和奖级；`FINAL_PAYOUT` 才允许显示确定的税前测算金额。若号码已确认而奖金尚未完整，可以显示“预计命中某奖级，奖金待官方数据确认”。这里的最终状态只表示应用取得并校验了足够的官方站点开奖数据，不表示彩票真实、有效、未撤单、未兑奖或具有官方验票效力。

V1 直连条件下必须满足：

- 同一次用户操作中取得两个明确发布的官方数据面，目标期号、日期、号码、基础奖级和详情地址一致，且下述彩种条件满足后即可进入 `FINAL_NUMBERS`，不再按固定 60 秒或次日 09:00 时间闸门延迟已发布结果。
- 大乐透主接口必须满足 `success=true`、`errorCode="0"`、目标期号唯一、`verify=1`、`lotteryDrawStatus=20`、`lotteryNotice=1`、号码合法且无未建模派奖，并与官网最新开奖聚合接口或同期开奖 PDF 一致。`prizeLevelList` 和当前规则所需金额全部可识别后，才进入 `FINAL_PAYOUT`。
- 大乐透最新聚合接口实际返回目标期且 `verify=1`、`lotteryNotice=1` 时，与主接口严格一致即可首次形成终态，不额外下载同一期 PDF。
- 大乐透非最新历史期在聚合接口不含目标期号时，只允许下载主记录绑定的同一期 `pdf.sporttery.cn` 公告；Android 使用 PDFBox Android、iOS 使用 PDFKit 提取文本，期号、日期、号码、全部奖级及奖金乘法由共享解析器复核。
- 双色球必须以 `findDrawNotice` 为主源；`forIssue` 只能辅助核对号码和基础奖级。号码、基础奖级、详情链接和当期特别规定状态均可确定，且两个接口同号时，才进入 `FINAL_NUMBERS`。
- 双色球处于已确认特别规定期间时，`FINAL_NUMBERS` 还必须取得可解析的 `fyjCount`、`fyjMoney`；字段缺失、格式异常或出现尚未建模的活动内容时停留在 `PUBLISHING` 或返回 `NEEDS_MANUAL_REVIEW`。
- 双色球 `2026014` 至 `2026075` 的特别规定范围已由官方公告和开奖字段交叉确认；`2026075.specialRuleInfo` 明确说明从 `2026076` 起退出。未来再次出现非空特别规定字段时必须先完成规则建模；只有全部已知政策和派奖字段都由主接口显式提供且为空时，才能把当期解释为普通状态，字段缺失不能等同于“不执行”。
- `2026092` 开奖公告显示开奖后奖池为 571,623,532 元，低于规则规定的 15 亿元特别规定进入阈值；`2026093` 至 `2026096` 的主、详情公告一致，福运奖、特别规定和其他派奖字段均为空。自 `2026096` 起不再维护逐期普通状态末期常量：只有主接口显式包含全部已知政策和派奖字段且均为空、两个接口的期号、日期、号码、基础奖级和详情链接一致时，才把当期解释为普通状态。字段缺失不能等同于空值，任一字段非空仍按未知活动阻断。
- 发布窗口不再使用固定等待时间推断完整性。任一数据面无记录、审核状态未完成、必要字段缺失或双源不一致时仍保持 `NOT_PUBLISHED`、`PUBLISHING` 或 `CONFLICT`；应用不在后台等待或自动轮询。
- `detailsLink` 或 `drawPdfUrl` 的存在本身不是最终状态；最终状态仍要求明确发布字段、完整结构和两个官方证据的数据一致性。
- PDF 响应必须保持精确最终 URL、`application/pdf`、不超过 1 MB、PDF 1.4、单页、未加密、无表单和固定生产器；平台文本顺序可匹配已测试布局，但不得放宽字段或金额关系。iOS 26.5 Simulator 已在无代理条件下完成 Darwin 主 JSON、官方 PDFKit 和双证据复测；若系统信任评估再次拒绝证书，仍必须返回 `NETWORK_UNAVAILABLE`，禁止跳过 TLS 信任评估。
- 当前结果只在用户主动刷新时更新，不高频轮询，不缓存或持久化原始响应。

任何一个源出现同一期号码变化、记录出现后消失、目标期号重复或与官方公告冲突时，立即进入 `CONFLICT`，停止自动测算。无记录永远只能表示开奖数据尚不可用。

多期票仍按精确单期协议执行，不使用宽区间响应一次性形成结论：

- 仅接受 1 至 20 期且能在当前安全边界内完整展开的连续期号，逐期独立保存 `DrawResult` 或明确不可用状态。
- `PUBLISHING` 和 `CONFLICT` 只影响对应期次，仍可继续核对后续已开奖期次。
- 首个 `NOT_PUBLISHED`、`NETWORK_UNAVAILABLE` 或 `SOURCE_UNAVAILABLE` 会停止本轮后续官网请求；未请求期次保留“本轮未查询”，不能解释为未中奖。
- 主动重试优先查询证据不足、规则尚需复核或中奖金额未完整的期次；全部期次都有中奖或未中奖结论且金额完整后，才允许汇总整票税前奖金。

## 5. 规则引擎原则

- 命中矩阵、奖金金额和临时派奖分层建模。
- 规则按生效期号版本化，不根据当前日期选择。
- 每注在每一期只领取其命中的最高奖级；单期先汇总有效子注、倍数和追加金额，多期再汇总各期已确认金额。
- V1 规则入口只接受单式和多注单式，期数限制为 1 至 20。复式、胆拖不属于已冻结的 V1.1 至 V1.5 路线；若在未排期后续版本实现，可展开成单注计算或使用组合数学计数，两种算法必须在测试中交叉验证。
- 一、二等奖等浮动奖及临时派奖金额直接使用当期官方开奖明细，不能本地估算。
- 基础规则不支持目标期号时返回 `RULE_UNSUPPORTED`，不能套用最近规则。

实现时优先读取当期 `specialRuleInfo`、`prizeSpecialInfo`、福运奖字段和奖级明细。不得仅凭本期开奖后奖池即时推导本期状态。

### 7.1 现行七奖级命中矩阵

| 前区命中 | 后区命中 | 奖级 |
|---:|---:|---|
| 5 | 2 | 一等奖 |
| 5 | 1 | 二等奖 |
| 5 | 0 | 三等奖 |
| 4 | 2 | 三等奖 |
| 4 | 1 | 四等奖 |
| 4 | 0 | 五等奖 |
| 3 | 2 | 五等奖 |
| 3 | 1 | 六等奖 |
| 2 | 2 | 六等奖 |
| 3 | 0 | 七等奖 |
| 2 | 1 | 七等奖 |
| 1 | 2 | 七等奖 |
| 0 | 2 | 七等奖 |

追加投注仅参与一、二等奖这两个浮动奖的奖金分配，规则规定追加奖金为对应基本投注单注奖金的 80%。实际测算只使用当期开奖明细中的追加单注奖金，不由客户端推算。官网分别以整数元公布基本与追加单注奖金，且规则明确浮动奖按元取整后的余额进入调节基金；两个已取整公布值之间的比例校验允许基本奖金 80% 相邻的向下或向上整数元，基本奖金可被 5 整除时仍只允许唯一整数值。

一、二等奖为浮动奖。三至七等奖根据开奖前奖池采用两套固定金额：

| 开奖前奖池 | 三等奖 | 四等奖 | 五等奖 | 六等奖 | 七等奖 |
|---|---:|---:|---:|---:|---:|
| 低于 8 亿元 | 5000 元 | 300 元 | 150 元 | 15 元 | 5 元 |
| 达到 8 亿元（含） | 6666 元 | 380 元 | 200 元 | 18 元 | 7 元 |

最终计算优先使用当期开奖接口中的单注奖金，不在客户端推算奖池状态。

官方依据：

- 2026 年变更公告：https://www.lottery.gov.cn/xxgk/tzgg/dlttz/20260115/10052026.html
- 2026 年正式规则 PDF：https://static.sporttery.cn/res_1_0/cmsv2/upload/docfile/202601/1511220935li.pdf
- 现行规则正文：https://www.lottery.gov.cn/bzzx/yxgz/20191119/1002858.html

现行票据约束：每注基本投注 2 元、每注追加投注 1 元，倍投范围 2 至 99 倍；单张彩票基本投注最高 20000 元，基本投注加追加投注最高 30000 元。未标注倍投的普通投注在领域模型中记为倍数 1。

### 7.2 奖级数据防御校验

2026 年变更公告明确新规则自 `26014` 期起执行；公告发布前已售且包含 `26014` 或之后奖期的多期票，从 `26014` 起的后续奖期也执行新规则。适配层和规则计算器必须共同执行：

- 当期开奖必须恰好包含一至七等奖七个基础奖级；缺失、重复或未知奖级均为无效数据。
- 三至七等奖不得携带追加奖金字段，且五个金额必须整体属于低于 8 亿元或达到 8 亿元（含）的同一套固定奖档，不能混用。
- 一、二等奖为浮动奖，基础金额只采用官网当期值；两者已发布的追加单注奖金必须符合对应基础奖金的 80%。
- 官网以整数元分别公布基本与追加单注奖金，不能把已取整的基本奖金再次限定为唯一四舍五入结果。第 `26096` 期一等奖 `6561952 / 5249561` 元落在向下整数，二等奖 `57893 / 46315` 元落在向上整数；校验接受 80% 相邻的两个整数元，超出该范围仍失败关闭。
- 奖级结构合法但必要金额尚未发布时只能进入 `FINAL_NUMBERS`；不得伪造 0 元，也不得进入 `FINAL_PAYOUT`。
- 未建立公告期号白名单的临时派奖继续返回 `PUBLISHING` 或 `NEEDS_MANUAL_REVIEW`，不能混入基础规则计算。

### 7.3 版本要求

| 版本 | 期号范围 | 奖级数 | V1 策略 |
|---|---|---:|---|
| `DLT_2026_01` | `26014` 起 | 7 | 完整支持 |
| `DLT_2019` | `19019` 至 `26013` | 9 | V1 不支持 |

## 8. 奖金计算

逐注计算过程：

```text
标准化一条投注
→ 根据期号选择 RuleVersion
→ 计算主区和次区命中数
→ 映射最高基础奖级
→ 从当期开奖奖级表取得单注奖金
→ 应用倍数
→ 大乐透追加票按当期开奖明细叠加符合条件的追加奖金
→ 汇总所有子注
```

税务提示可以展示，但 V1 返回税前官方单注金额和税前汇总金额，不自行给出实际到手金额承诺。

当期奖级数据缺失、奖金包含无法解析说明、临时活动未知或规则版本未知时，返回 `NEEDS_MANUAL_REVIEW` 或 `RULE_UNSUPPORTED`。

## 9. 测试要求

- 双色球穷举红球命中 0 至 6、蓝球命中 0 至 1 的全部矩阵。
- 大乐透穷举前区命中 0 至 5、后区命中 0 至 2 的全部矩阵。
- 每个命中组合验证最高奖级唯一性。
- V1 对单式、多注单式、倍数、大乐透追加及受控的 1 至 20 期连续票分别测试。
- 复式、胆拖、超过 20 期及跨年度未知序列只保留后续设计用例，不纳入 V1 实现；补打票仅在号码、期号、期数、倍数、追加属性和金额完整闭环时复用现有单式或多注单式规则测试。
- 大乐透奖级数据必须覆盖七奖级完整性、两套固定奖档、混档、未知或重复奖级、追加 80% 元级上下取整边界和金额缺失状态。
- 覆盖双色球 `2026013/2026014` 和大乐透 `26013/26014` 规则边界。
- 固化人工构造、经过最小化的同结构契约夹具和公告摘要用于离线测试，不把福彩原始响应提交 Git。线上 smoke test 不阻断每次 CI。
- 测试空列表、HTTP 200 业务失败、类型漂移、未知奖级、不可解析奖金、数据修订和网络超时。

## 10. 数据源替换路径

未来增加自有服务器时，仅替换 `DrawRepository` 的远端实现：

```text
V1：KMP 客户端 → 官网内部 JSON
未来：KMP 客户端 → 自有 BFF → 获授权的数据源/官网源
```

UI、票面识别、领域模型和规则引擎不应因数据源替换而改写。
