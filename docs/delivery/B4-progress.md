# B4 Android/iOS 票面人工校正进展记录

记录日期：2026-08-19

## 状态结论

B4 已从静态核对页推进到可用的共享人工校正流程：Android/iOS 真实本地 OCR 草稿可以编辑彩种、期号、逐注号码、倍数、大乐透追加和票面金额，并在每次修改后执行完整领域校验。彩种和投注行结构可靠时，期号、倍数、追加或金额缺失及属性矛盾会保留已识别字段并直接进入校正页；多个期号或金额候选会保留原图和候选值，但为避免混入另一张彩票，不复用其他 OCR 草稿，而是进入全字段空白的“对照原图录入”。未知倍数和追加保持空值，只有用户明确选择、图片预览可用且票面状态合法时才能生成 `ConfirmedTicket` 并继续。

B4 仍处于进行中。多个期号和金额候选已在当前 Android/iOS 模拟器完成交互回归，OCR 引擎名及彩种、期数等字段的原始置信度也已贯通到当前校正状态，并建立了现有 13 张探索图的分平台匿名初步分布；逐 token 真值、平台分别校准、低置信视觉标记和足量真实票样验收尚未完成，当前不能据此承诺任何省份、终端或票面版式。

## 本轮已实现

### 校正状态与领域对象

- 新增 Android/iOS 共用的不可变 `TicketReviewState` 和单一 `TicketReviewAction`，所有输入通过控制器更新，不在 Composable 内保存第二份业务状态。
- OCR 初始字段标记为 `OCR`；用户实际修改的字段标记为 `USER`；按当前投注结构更新金额时标记为 `DERIVED`。
- 保留投注行原始顺序与 OCR 原文，号码在生成 `ConfirmedTicket` 时按升序保存，重复行不会去重。
- OCR 可保留真实投注期数供核对，领域校验现接受 1 至 20 期受控连续票，并按全部期数严格核对金额；超过 20 期或跨年度未知序列继续阻断。倍数只接受 1 至 99；未知倍数和大乐透追加保持 `null` 并阻断确认，用户选择后记录为 `USER`；双色球会按规则清除不适用的追加属性。
- 抽取统一 `TicketAmountCalculator`，保守解析器、人工校正和 `TicketValidator` 使用同一套整数分金额公式，不使用浮点数。
- `TicketFieldRegion` 现保留平台校准前的原始置信度；彩种、期号、投注行、倍数、追加、投注期数和金额均沿用原图证据区域携带该值。
- 合并片段或跨行字段采用失败关闭聚合：只有全部必要片段均提供合法分数时才取最低值，任一片段缺失或越界都保持未知，不会静默丢弃低质量证据。
- `AppScreen.Review` 只在当前 OCR 流程内存中保留引擎名和字段分数；手动录入为 `null`，返回后的无图确认快照会清空，字段分数不持久化、不显示为未经校准的结论，也不参与确认闸门。当前不会设置 Android/iOS 共用低分阈值。

### Android/iOS 共用界面

- 彩种使用互斥选择控件，期号和票面金额使用可校验输入框。
- 每注分别提供前区/红球和后区/蓝球号码球编辑器，选中数量达到单式上限后需先取消旧号码再选择新号码。
- 已识别倍数使用带加减图标的步进器，未知倍数提供明确的“确认 1 倍”入口；大乐透基本/追加使用无默认选中的互斥选项；投注期数使用 1 至 20 的加减步进器，金额随期数实时重新推导，无法安全展开的多期值同步显示领域阻断原因。
- 同时展示 OCR 票面金额和按当前投注结构计算的理论金额；用户可明确选择“使用计算金额”，不会静默覆盖 OCR 值。
- 字段问题和汇总问题在当前页面内联显示；确认按钮只有在 `TicketValidator` 完全通过时启用。
- 期号和金额输入保留键盘 `Done` 动作，并增加可见的勾选完成按钮；iOS 数字键盘无法自行收起时仍可明确结束输入。
- 多个合法期号或合计金额不会自动任选；校正页在原图下方显示可横向访问的候选选项，未选择时保持错误提示，用户选择后按 `USER` 输入继续校验。

### 原图预览与字段定位

- 共享保守解析器保留 OCR 证据的归一化坐标，并分别关联彩种、期号、每一注号码、倍数、追加摘要、投注期数和票面金额；可恢复草稿及冲突期数结果同样携带安全字段区域。
- 校正页提供固定高度的原图预览和“整票/彩种/期号/逐注/倍数/追加/期数/金额”切换控件；选择字段后使用带上下文的裁切视口，并在原图中叠加高亮区域。彩种框归一化高度超过 `0.25` 时只保留原始置信度，不显示误导性定位入口。
- 预览位图最长边限制为 1600 像素。Android 使用 `BitmapFactory` 采样并在必要时精确缩小，iOS 使用 Okio 读取私有 JPEG 并由 Skia 按二次幂缩略解码，避免校正页长期持有完整 OCR 尺寸位图。
- 真实识别流程在预览加载期间或加载失败后不会启用确认；加载失败时要求用户返回并重新导入，防止在失去原图核对依据时继续。
- Windows/macOS 解码实现保持空结果，桌面真实 OCR 和校正预览继续按 ADR-011 延期，不扩大移动 V1 范围。

### 流程与安全边界

- 移除真实 OCR 草稿的主动结束阻断，真实票面现在可以进入人工校正并生成不可变确认票据。
- `TicketParseResult.NeedsCorrection` 可携带安全草稿；控制器收到草稿时进入校正页并保留已识别字段，收到无草稿结果时保留临时图片并进入空白手动录入，不把不可靠 OCR 值带入编辑状态。
- 目前可恢复期号、倍数、追加或金额缺失，以及金额、倍数或追加属性矛盾；受损摘要中的期数和倍数只有在玩法与合计锚点完整时才恢复，未知值不会参与金额推导。完整的受控多期草稿可确认并进入逐期查询；多个期号或金额候选只作为原图辅助录入选项，不带入可能混票的号码和属性，未知彩种、号码结构异常、复式、胆拖和补打继续硬阻断。
- 校验失败保持当前编辑状态和临时图片，便于继续修正；确认成功或退出流程后立即清理应用私有临时图片。
- 本记录形成后，Android/iOS 容器已在 B5 接入真实官网仓库和本地规则引擎；B4 仍只对票面人工校正能力负责，不因此视为通过真实票样验收。
- Windows/macOS 共用代码仍可编译，但桌面客户端已延期到 V1.1 或后续，不属于本批移动 V1 验收范围。

## 自动化覆盖

- 覆盖未修改字段保持 OCR 来源、用户修改期号和号码后记录 USER 来源、倍数变化触发金额不一致、显式金额推导恢复合法状态、空金额阻断。
- 覆盖大乐透草稿切换为双色球后，对期号、号码、追加和金额完成校正并恢复为合法票据。
- 覆盖真实 OCR 容器进入校正页并确认、非法期号停留在确认闸门、不查询开奖且不提前清理票图。
- 覆盖期号、倍数、追加或金额缺失及属性矛盾携带草稿；覆盖多个期号或金额只携带去重候选和合并定位区域、不携带其他草稿，未知彩种和号码结构异常同样不携带草稿。
- 覆盖控制器对可恢复结果保留图片并进入校正页，以及无安全草稿时保留原图、创建空白投注行、允许新增投注行并在退出后清理图片。
- 覆盖缺失期号必须由用户补齐并记录 `USER` 来源，缺失金额必须由用户输入或明确采用理论金额。
- 覆盖未知倍数和追加保持空值、金额停止推导、控制器分别维持确认闸门，以及用户逐项明确选择后记录 `USER` 来源并恢复合法状态。
- 覆盖大乐透追加、多注、倍数金额计算，双色球基本金额，以及非法追加和追加行数拒绝。
- 覆盖解析结果对彩种、期号、逐注号码、倍数、追加、期数和金额区域的映射，以及控制器对可恢复草稿区域的完整传递。
- 覆盖标题和摘要单位受损、摘要单位被误成连续数字、歧义或冲突证据拒绝恢复、默认单期不生成期数区域、冲突期数保留证据、分区符漏识别、侧边纵排文字跨越多注，以及完整多期草稿进入确认、全期金额校验、超过上限和年度边界阻断。
- 覆盖整票视口、字段上下文裁切和边界收敛；覆盖 Android 缺失文件安全失败和 iOS 有效 JPEG 缩略解码。
- 覆盖单行原始分数透传、分散片段取最低值、彩种联合证据取最低值、同值标题选择最小精确框、任一片段缺失时字段分数保持未知、超大彩种框隐藏，以及 OCR 引擎名只在当前图片校正流程存在。
- 覆盖匿名诊断只能接收解析状态、字段分类和分数，引擎名控制字符清理、越界分数转为未知、平台日志异常不影响 OCR 流程，以及控制器每次成功解析只提交一条匿名样本。

## 未完成范围

- OCR 原始置信度已完成字段级内存透传和现有 13 图的分平台初步分布，但尚无逐 token 双人真值、正确/错误条件分布与校准阈值，低置信字段没有视觉标记。
- 安全 OCR 草稿只在数量、范围、升序和坐标分区同时成立时合并分散片段；证据不足时不会自动拆分或混用可疑行，而是进入空白多注录入。
- 真实开奖查询、规则计算和结果页已由 B5 接入；B4 的低置信字段和足量票样验收仍未完成。候选交互已经通过当前双模拟器回归，但合成票面不能替代真实歧义票样。
- iOS Simulator 已验证生产格式 JPEG 的缩略解码；Android Host 环境没有真实 `BitmapFactory`，因此 Android 有效图片解码仍需真机验证。
- Android 16 与 iOS 26.5 模拟器已使用同一原始 JPEG 完成本轮五注多期 OCR 草稿回归，两端均得到 1 倍基本投注、10 期及与理论值一致的 100 元票面金额；原图辅助录入、iOS 软键盘完成操作和临时图片清理也已回归。目标 Android/iPhone 物理真机上的完整字段切换、高亮、触控、横竖屏和动态字号验收仍未完成。
- 多期逐期开奖的控制器与结果状态已经接入，但该五注探索票尚未在 Android/iPhone 物理真机完成“图片 → 确认 → 逐期官网查询 → 结果页 → 重试”的完整交互验收。

## 下一步

1. 继续只在当前 Android/iOS 模拟器补充可证明为 2025 年及以后出票的大乐透单期基本/追加票及更多双色球同版式样本，验证原图预览、字段定位、期数校正及完整人工确认交互；公开网络图不计入白名单或准确率。
2. 使用可获得的真实候选歧义样本在当前双模拟器复核候选定位、选择和全字段空白回退；只有未来证据能证明字段来自同一张票时，才评估复用其他 OCR 草稿。
3. 为分平台初步分布补充逐 token 双人真值和多拍摄条件样本；分别完成正确/错误条件分布与阈值校准后，再实现低置信视觉标记。
4. 配合 B5 在当前双模拟器复核“导入 → 校正 → 真实查询 → 结果或安全重试”的完整交互；相机和物理真机发布矩阵不在当前执行范围内冒充完成。
