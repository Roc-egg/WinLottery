# V1.4 AI 历史数据分析交付记录

文档状态：进行中

立项日期：2026-08-27

目标版本：`1.4.0 (6)`

目标平台：Android、iOS

## 1. 当前目标

V1.4 在 V1.3 已校验的会话级历史开奖之上，提供用户主动触发、逐次确认的 AI 分析。首发采用用户自备密钥，不建设自有服务器，不持久化密钥、历史快照或分析结果；模型输出必须经过严格结构解析和本地彩票规则复核，不能改写官方开奖或宣称提高中奖概率。

## 2. 冻结边界

- 运行时由用户选择 AI 服务商、HTTPS 地址和模型，仓库不提供默认启用的供应商、共享密钥或后台代理。
- 密钥只在当前进程会话中使用，不写入 Room、文件、系统钥匙串、日志、崩溃信息或导出包；应用重启后需要重新填写。
- 只发送 V1.3 已严格校验的 `50 / 80 / 120 / 300 / 500` 期规范化开奖和本次分析参数，不发送票图、OCR、本机票据、设备或身份数据。
- 每次请求前展示实际服务商、HTTPS 主机、模型、样本范围、快照标识、模板、候选数量、发送字段、字节数、输出上限和费用责任，并由用户明确确认。
- 一次确认最多发送一次请求，不自动请求、不后台轮询、不自动重试、不静默切换服务商；输入最多 `128 KiB`，输出最多 `2048` token，超时 60 秒。
- 候选数量固定为 `1..5`。输出使用版本化严格 JSON Schema，并再次执行本地彩种、快照和号码合法性校验；任一候选非法时整批失败。
- 拒答、截断、内容过滤、非法 JSON、缺字段、超时、限流、鉴权失败和服务不可用全部失败关闭，不使用随机或数学结果冒充 AI 输出。
- 分析结果只保留当前会话，当前版本不修改 Room 模式、票据导入导出格式和官方开奖结果。

## 4. 完成条件

- 相同规范化历史数据必须生成相同快照标识，请求字段与确认页展示完全一致，确认后修改任何配置都不能复用旧授权。
- 关闭 AI、取消确认或离开流程时不产生模型请求；一次确认即使失败也不能自动重试。
- 密钥、完整请求和完整响应不进入数据库、文件、日志、崩溃信息或导出包。
- 严格结构成功、拒答、截断、内容过滤、非法 JSON、Schema 漂移、非法号码、缺字段、超时、限流、鉴权失败和服务不可用均有共享或适配器测试。
- Android/iOS 共用同一领域模型、状态机和 Compose 页面；双端标准字号竖横屏无重叠，500 期发送预览和最多 5 注结果可正常阅读。
- `1.3.0 (5) → 1.4.0 (6)` 双虚拟机 Release 覆盖升级保留现有 Room 记录；V1.4 不新增数据库迁移。

## 5. 已完成验证

### 2026-08-27：共享领域契约与严格本地校验

- `:shared:domain` 新增综合历史分析、频次与遗漏、分布结构三种版本化模板，候选数量严格限制为 `1..5`；模型解析结果在本地校验前使用独立未信任模型，不会直接进入界面。
- 历史快照复用 V1.3 走势完整性校验，只保留彩种、期号、开奖日期和主次号码；固定 JSON 字段顺序后计算 SHA-256，相同数据不受输入顺序影响，任一期内容变化都会改变标识。
- `50 / 80 / 120 / 300 / 500` 五档均从最近期开奖精确截取，500 期规范化数据未超过冻结的 96 KiB 快照上限；样本不足、混入彩种、非法号码、期号空档、错误日期和超限均失败关闭。
- 本地输出校验覆盖 Schema 版本、彩种、快照标识、摘要、候选数量、双彩种号码数量/范围/唯一性/升序、重复候选和单注说明；任一问题存在时整批拒绝。
- 领域模块只复用版本目录已有的 `kotlinx.serialization-json` 和 Okio，不升级依赖或工具链。
- `./gradlew spotlessCheck :shared:domain:jvmTest :shared:domain:iosSimulatorArm64Test :shared:domain:compileAndroidMain`：通过。

## 6. 当前结论

V1.4 已完成立项、安全边界、共享领域契约、规范化历史快照和严格本地输出校验。下一步实现首个可配置 Responses 风格 AI Provider 适配器，覆盖严格结构请求、响应解析、失败映射、超时、请求体上限和无敏感日志边界。本页只记录可验收节点，不以计划项替代完成证据。
