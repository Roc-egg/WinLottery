# V1.4 AI 历史数据分析交付记录

文档状态：进行中

立项日期：2026-08-27

目标版本：`1.4.0 (6)`

目标平台：Android、iOS

## 1. 当前目标

V1.4 在 V1.3 已校验的会话级历史开奖之上，提供用户主动触发、逐次确认的 AI 分析。首发采用用户自备密钥，不建设自有服务器，不持久化密钥、历史快照或分析结果；模型输出必须经过严格结构解析和本地彩票规则复核，不能改写官方开奖或宣称提高中奖概率。

## 2. 冻结边界

- 运行时由用户选择 AI 服务商、HTTPS 地址和模型，仓库不提供默认启用的供应商、共享密钥或后台代理。
- 密钥只在当前进程会话中使用，不写入 Room、文件、系统钥匙串、日志、崩溃信息或导出包；应用重启后需要重新填写。
- 只发送 V1.3 已严格校验的 `50 / 80 / 120 / 300 / 500` 期规范化开奖和本次分析参数，不发送票图、OCR、本机票据、设备或身份数据。
- 每次请求前展示实际服务商、HTTPS 主机、模型、样本范围、快照标识、模板、候选数量、发送字段、字节数、输出上限和费用责任，并由用户明确确认。
- 一次确认最多发送一次请求，不自动请求、不后台轮询、不自动重试、不静默切换服务商；输入最多 `128 KiB`，输出最多 `2048` token，超时 60 秒。
- 候选数量固定为 `1..5`。输出使用版本化严格 JSON Schema，并再次执行本地彩种、快照和号码合法性校验；任一候选非法时整批失败。
- 拒答、截断、内容过滤、非法 JSON、缺字段、超时、限流、鉴权失败和服务不可用全部失败关闭，不使用随机或数学结果冒充 AI 输出。
- 分析结果只保留当前会话，不修改官方开奖结果。2026-10-20 起按 ADR-026 把历史开奖保存到本机（Room 模式 v1→v2，仅新增两张历史开奖表）；2026-10-21 起按 ADR-027 把查询开奖的已开奖期次保存到本机（Room 模式 v2→v3，仅新增 `draw_results` 表）；票据表和导入导出 JSON 格式不变，导出包中的 `roomSchemaVersion` 改为票据表模式版本。

## 4. 完成条件

- 相同规范化历史数据必须生成相同快照标识，请求字段与确认页展示完全一致，确认后修改任何配置都不能复用旧授权。
- 关闭 AI、取消确认或离开流程时不产生模型请求；一次确认即使失败也不能自动重试。
- 密钥、完整请求和完整响应不进入数据库、文件、日志、崩溃信息或导出包。
- 严格结构成功、拒答、截断、内容过滤、非法 JSON、Schema 漂移、非法号码、缺字段、超时、限流、鉴权失败和服务不可用均有共享或适配器测试。
- Android/iOS 共用同一领域模型、状态机和 Compose 页面；双端标准字号竖横屏无重叠，500 期发送预览和最多 5 注结果可正常阅读。
- `1.3.0 (5) → 1.4.0 (6)` 双虚拟机 Release 覆盖升级保留现有 Room 记录；ADR-026、ADR-027 新增的 v1→v2→v3 显式迁移必须在覆盖升级中保留全部票据，并能导入升级前导出的备份。

### 2026-08-27：首个 Responses 风格 AI Provider

- 新增用户自备服务配置校验，仅允许不含账号、查询参数和片段的完整 HTTPS 地址；服务商、模型和会话密钥执行保守文本边界，配置调试文本固定隐藏密钥。
- 新增 AI 专用 Ktor 客户端，禁止重定向，不安装请求日志或上层重试，并在 Android/JVM OkHttp 引擎显式关闭连接失败重试；单次请求和套接字等待上限为 60 秒。
- 请求固定使用 `store=false`、`truncation=disabled`、`max_output_tokens=2048` 和 `text.format` 严格 JSON Schema；确认指纹覆盖服务商、目标地址、模型和完整无密钥请求体，配置或请求变化后旧确认无法复用。
- 密钥只进入 `Authorization` 请求头，请求体和确认预览均不包含密钥；3xx 在原地址阻断，错误正文不回显，成功响应最多读取 64 KiB。
- 已覆盖严格输出成功、拒答、token 截断、内容过滤、非法 JSON、额外字段、非法号码、HTTP 鉴权/限流/服务异常、重定向、超时、网络断开和调用方取消；所有失败均不自动重试。
- `./gradlew spotlessCheck :shared:data:jvmTest :shared:data:iosSimulatorArm64Test :shared:data:compileAndroidMain`：通过。
