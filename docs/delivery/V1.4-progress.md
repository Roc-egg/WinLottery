# V1.4 AI 历史数据分析交付记录

文档状态：进行中

立项日期：2026-08-27

目标版本：`1.4.0 (6)`

目标平台：Android、iOS

## 1. 当前目标

V1.4 在 V1.3 已校验的会话级历史开奖之上，提供用户主动触发、逐次确认的 AI 分析。首发采用用户自备密钥，不建设自有服务器，连接配置和密钥只加密保存在本机（ADR-031），不持久化历史快照或分析结果；模型输出必须经过严格结构解析和本地彩票规则复核，不能改写官方开奖或宣称提高中奖概率。

## 2. 冻结边界

- 运行时由用户选择 AI 服务商、HTTP 或 HTTPS 地址（ADR-032，HTTP 提示不加密）和模型，模型可从服务商读取列表后选择，仓库不提供默认启用的供应商、共享密钥或后台代理。
- 连接配置和密钥按 ADR-031 只保存在本机：Android 用 Keystore 加密、iOS 存入仅本设备的钥匙串，桌面只保存服务商、地址和模型、密钥只在本次运行有效；不写入 Room、日志、崩溃信息或导出包。
- 只发送 V1.3 已严格校验的 `50 / 80 / 120 / 300 / 500` 期规范化开奖和本次分析参数，不发送票图、OCR、本机票据、设备或身份数据。
- 每次请求前展示实际服务商、接收主机及是否加密、模型、样本范围、快照标识、模板、候选数量、发送字段、字节数、输出上限和费用责任，并由用户明确确认。
- 一次确认最多发送一次请求，不自动请求、不后台轮询、不自动重试、不静默切换服务商；输入最多 `128 KiB`；输出上限与超时按 ADR-034 由用户在 4K 至 32K token 中选择，默认 8K，超时随上限放宽。
- 候选数量固定为 `1..5`。输出使用版本化严格 JSON Schema，并再次执行本地彩种、快照和号码合法性校验；任一候选非法时整批失败。
- 拒答、截断、内容过滤、非法 JSON、缺字段、超时、限流、鉴权失败和服务不可用全部失败关闭，不使用随机或数学结果冒充 AI 输出。
- 分析结果只保留当前会话，不修改官方开奖结果。2026-10-20 起按 ADR-026 把历史开奖保存到本机（Room 模式 v1→v2，仅新增两张历史开奖表）；2026-10-21 起按 ADR-027 把查询开奖的已开奖期次保存到本机（Room 模式 v2→v3，仅新增 `draw_results` 表）；票据表和导入导出 JSON 格式不变，导出包中的 `roomSchemaVersion` 改为票据表模式版本。

## 4. 完成条件

- 相同规范化历史数据必须生成相同快照标识，请求字段与确认页展示完全一致，确认后修改任何配置都不能复用旧授权。
- 关闭 AI、取消确认或离开流程时不产生模型请求；一次确认即使失败也不能自动重试。
- 密钥、完整请求和完整响应不进入数据库、文件、日志、崩溃信息或导出包。
- 严格结构成功、拒答、截断、内容过滤、非法 JSON、Schema 漂移、非法号码、缺字段、超时、限流、鉴权失败和服务不可用均有共享或适配器测试。
- Android/iOS 共用同一领域模型、状态机和 Compose 页面；双端标准字号竖横屏无重叠，500 期发送预览和最多 5 注结果可正常阅读。
- `1.3.0 (5) → 1.4.0 (6)` 双虚拟机 Release 覆盖升级保留现有 Room 记录；ADR-026、ADR-027 新增的 v1→v2→v3 显式迁移必须在覆盖升级中保留全部票据，并能导入升级前导出的备份。

### 2026-11-09：AI 输出上限改为可选，超时随上限放宽（ADR-034）

- 起因：用户按 ADR-033 重新请求后得到“模型输出达到 token 上限，结果未完成”，固定的 2048 token 不够中文摘要与理由，推理模型的思考也计入上限。
- 连接配置新增“输出上限”（4K、8K、16K、32K token，默认 8K），随配置保存在本机并写入请求体与确认指纹；超时改为 60 秒加按每秒 40 token 生成满上限的时间，成功响应读取上限放宽到 1 MiB；提示词要求摘要 300 字、每注理由 100 字以内。截断时说明当前上限和服务商报告的思考 token 数，并提示调高。
- 验证：领域测试覆盖上限取值与超时计算；协议测试覆盖三种格式请求体使用所选上限、指纹随上限变化、截断说明的上限与思考 token；控制器测试覆盖旧配置用默认上限、修改写回与重启恢复。`./gradlew spotlessCheck jvmTest testAndroidHostTest`（JVM 588、Android 518）与 `:shared:compileKotlinIosSimulatorArm64` 通过。未在模拟器或真机上走界面，交给用户人工验证。

### 2026-11-07：AI 连接支持三种接口格式与 Base URL，失败显示服务商说明（ADR-033）

- 起因：用户在小米手机上请求 AI 只得到“AI 服务拒绝当前请求结构或参数”。该文案对应服务商返回的 4xx，应用此前只按 OpenAI Responses 请求且不展示错误正文，无法判断是接口不支持、参数不被接受还是模型不存在。

### 2026-11-07：修复输入框弹出键盘后立即收起、失去焦点及键盘上方空白

- 原因一：`AppShell` 把 `imePadding` 加在测量尺寸的 `BoxWithConstraints` 上，竖屏手机弹出键盘后可用高度低于 600dp 紧凑阈值，一级页面外壳从底部导航切换为紧凑顶部导航，正文被重建，输入框失焦、键盘收起，高度恢复后又切回原布局。影响“记录”页搜索框和“AI”页全部输入框。
- 原因二：`MainActivity` 未声明 `windowSoftInputMode`，部分手机系统会在键盘弹出时整体上推窗口，与 Compose 的键盘内边距叠加，在底部导航与键盘之间留出空白，顶部栏也被推出屏幕；iOS 默认的 `OnFocusBehavior.FocusableAboveKeyboard` 同样会整体上推视图。
- 修复：导航形态只按窗口尺寸（扣除状态栏与导航栏）决定；键盘只让正文内容区避让，并扣除被键盘遮住的底部导航高度，顶部栏与底部导航保持原位。Android 声明 `adjustResize`，iOS 设为 `OnFocusBehavior.DoNothing`，键盘避让统一由共享外壳处理。
- 验证：锁定模拟器 `Medium_Phone_API_36.1` 上用修复前后调试包对照，修复前点击记录页搜索框、AI 页输入框 3 秒后键盘收起且焦点丢失；修复后窗口为 `adjust=resize`，记录页、AI 页“模型”输入框和手动录入页“合计金额”输入框均保持键盘与焦点，聚焦输入框紧贴键盘上方，底部导航在键盘弹出前后位置不变，无空白。`./gradlew spotlessCheck :shared:jvmTest :shared:testAndroidHostTest :shared:iosSimulatorArm64Test` 通过。原先出现空白的实体手机和 iOS 尚未复测键盘交互。

### 2026-10-24：识别前校正整页朝向（ADR-029）
